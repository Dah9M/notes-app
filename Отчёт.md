# Отчёт: экспорт и сбор метрик Notes App в VictoriaMetrics

## 1. Цель и стек

В minikube-кластере настроен сбор технических и бизнес-метрик Notes App и метрик
PostgreSQL. Используется Pull-модель: vmagent опрашивает endpoints приложения
и экспортера, затем отправляет значения в TSDB VictoriaMetrics.

| Компонент          | Технология / версия                                   | Назначение                                 |
|--------------------|-------------------------------------------------------|--------------------------------------------|
| Backend            | Java 21, Spring Boot Spring Data JPA                  | API заметок, регистрации и входа           |
| Экспорт приложения | Spring Boot Actuator + Micrometer Prometheus registry | JVM, HTTP, пул соединений и бизнес-метрики |
| База данных        | PostgreSQL                                            | Хранение пользователей, заметок и тегов    |
| Экспорт БД         | prometheus-community/postgres-exporter                | Экспорт статистики PostgreSQL              |
| Хранилище          | VictoriaMetrics                                       | Временные ряды и HTTP API запросов         |
| Сборщик            | vmagent                                               | Service discovery, scrape и remote write   |
| Окружение          | minikube, Kubernetes                                  | Общий кластер приложения и мониторинга     |

Frontend реализован на HTML/CSS/JavaScript; файлы раздаёт Python-сервер.
В этой работе метрики приложения экспортирует Java-backend. Grafana не используется.

## 2. Архитектура и установка

```text
namespace notes                           namespace monitoring

backend pod №1 :8082/actuator/prometheus ─┐
                                        ├──→ vmagent :8429 ──→ VictoriaMetrics :8428
backend pod №2 :8082/actuator/prometheus ─┤        │                     │
                                        │    Kubernetes API        PVC 5 GiB
postgres-0                              │    pod discovery
  ├── PostgreSQL :5432                  │
  └── postgres-exporter :9187/metrics ───┘
```

В namespace `monitoring` установлены официальные Helm-чарты:

- `victoria-metrics-single` **0.49.0**, релиз `vm-single`;
- `victoria-metrics-agent` **0.50.0**, релиз `vmagent`.

Оба компонента имеют по одной реплике. Для VictoriaMetrics выделен постоянный
том 5 GiB со StorageClass `standard`, срок хранения метрик — 7 дней.

Использованные конфигурации:

- [VictoriaMetrics values](k8s/monitoring/victoria-metrics-values.yaml).
- [vmagent values](k8s/monitoring/vmagent-values.yaml).
- [Backend Deployment](k8s/backend/backend.yaml).
- [PostgreSQL StatefulSet с exporter](k8s/postgres/postgres.yaml).
- [Secret подключения exporter](k8s/monitoring/postgres-exporter-secret.yaml).

Установка:

```bash

helm install vm-single vm/victoria-metrics-single \
  --version 0.49.0 --namespace monitoring --create-namespace \
  -f k8s/monitoring/victoria-metrics-values.yaml

helm install vmagent vm/victoria-metrics-agent \
  --version 0.50.0 --namespace monitoring \
  -f k8s/monitoring/vmagent-values.yaml
```

Адрес remote write внутри кластера:
`http://vm-single.monitoring.svc.cluster.local:8428/api/v1/write`.

## 3. Метрики рантайма и фреймворка

В [pom.xml](backend/pom.xml) подключены `spring-boot-starter-actuator` и
`micrometer-registry-prometheus`. Actuator предоставляет готовую
инструментализацию JVM и компонентов Spring Boot.

Endpoint без авторизации: **`http://<pod-ip>:8082/actuator/prometheus`**.
Основной API работает на `8080`.

Настройки находятся в [application.yml](backend/src/main/resources/application.yml).
Добавлен общий label `application="notes-backend"`.

| Метрика                              | Что показывает                              |
|--------------------------------------|---------------------------------------------|
| `jvm_memory_used_bytes`              | Используемую память JVM по областям и пулам |
| `jvm_threads_live_threads`           | Количество живых потоков                    |
| `process_uptime_seconds`             | Время работы процесса                       |
| `hikaricp_connections_active`        | Число занятых соединений пула БД            |

| `http_server_requests_seconds_sum`   | Суммарную длительность запросов в секундах  |

## 4. Бизнес-метрики

В [BusinessMetrics.java](backend/src/main/java/com/notesapp/metrics/BusinessMetrics.java)
реализованы пять отдельных Micrometer Counter. Они регистрируются при запуске
со значением 0 и присутствуют в экспорте до первого бизнес-события.

| Метрика                          | Событие                              | Место увеличения       |
|----------------------------------|--------------------------------------|------------------------|
| `notesapp_registrations_total`   | Успешно сохранённая регистрация      | `AuthService.register` |
| `notesapp_logins_total`          | Успешная проверка логина и пароля    | `AuthService.login`    |
| `notesapp_notes_creations_total` | Создание заметки                     | `NoteService.create`   |
| `notesapp_notes_updated_total`   | Успешная операция обновления заметки | `NoteService.update`   |
| `notesapp_notes_deleted_total`   | Удаление заметки                     | `NoteService.delete`   |

Счётчики увеличиваются после успешного выполнения операции. При наличии
внешней транзакции инкремент переносится в `afterCommit`: rollback не увеличивает
метрику. Неверный пароль, конфликт регистрации, отсутствующая заметка и отказ
валидации не считаются успехом.

## 5. Экспорт метрик PostgreSQL

В StatefulSet PostgreSQL добавлен второй контейнер с образом
`quay.io/prometheuscommunity/postgres-exporter:v0.18.1`. Контейнеры одного pod
используют общее сетевое пространство: exporter подключается к
`localhost:5432/notesdb?sslmode=disable` и предоставляет `/metrics` на `9187`.

Для подключения создана роль `metrics_exporter` с правами `pg_monitor` и
`CONNECT` к `notesdb`. Учётные данные передаются через Secret
`postgres-exporter-secret`, адрес — через `DATA_SOURCE_URI`.

Примеры метрик:

- `pg_up` — возможность exporter подключиться к PostgreSQL;
- `pg_stat_database_numbackends` — число подключений к базе;
- `pg_stat_database_xact_commit` — статистика завершённых транзакций.

`up=1` подтверждает успешный HTTP scrape, а **`pg_up=1`** — доступность БД для
exporter. Поэтому при проверке используются оба показателя.

## 6. Service discovery по аннотациям

Аннотации находятся в `spec.template.metadata.annotations` и попадают на pod.
Для backend:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "8082"
prometheus.io/path: "/actuator/prometheus"
```

Для PostgreSQL с exporter:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "9187"
prometheus.io/path: "/metrics"
```

В vmagent настроен job `notes-pods` с `kubernetes_sd_configs`, `role: pod` и
ограничением namespace `notes`. Отбирает аннотированные pod в фазе
Running, исключает init-контейнеры, выбирает containerPort по аннотации и
устанавливает путь в `__metrics_path__`. Также добавляются labels `namespace`,
`pod` и `container`.

Интервал scrape — **15 секунд**, timeout — **10 секунд**. Чарт создаёт
ServiceAccount и RBAC для Kubernetes API. IP pod не зафиксированы: после их
пересоздания адреса обновляются через discovery. Обе реплики backend собираются
независимо, без балансировки через Service приложения.
